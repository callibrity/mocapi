## Remaining before tagging

### 1. Authorization SHOULDs (ADR-0022 "deferred SHOULD-level")
Reopened against the "adhere to SHOULD by default" preference. **Decided and
implemented in ADR-0029.**
- [x] **(a)** `resource_metadata` on the 401 challenge — **already satisfied**;
  Spring Security 7.0.5's `BearerTokenAuthenticationEntryPoint` emits it
  unconditionally and `MocapiOAuth2AutoConfigurationTest` already asserts it. The
  "needs a custom entry point" premise was a Spring 6.x fact. The `scope` parameter
  on a bare 401 is **declined** as duplicate of `scopes_supported`.
- [x] **(b)** 403 `insufficient_scope` — resource-level **implemented** via the new
  optional `mocapi.oauth2.required-scopes` property (empty default = today's
  `authenticated()` behavior). The originally planned "zero new code, do it in an
  `McpFilterChainCustomizer`" route **does not work** — `anyRequest()` can't be
  configured twice on the shared registry (startup failure), and `requestMatchers`
  after it is never evaluated (first-match-wins → silent non-enforcement). The
  authorization guide had been recommending exactly that; corrected. Per-tool
  step-up **declined** (visibility ≡ invocation, ADR-0012).
- [x] Covered by `McpRequiredScopesTest` (8 tests), including AND-not-OR, the
  challenge contents, 401-not-403 for missing credentials, and the
  `allOf`-grants-on-empty trap. Verified to fail against a broken implementation.

### 4. Release gate → tag
- [x] `mvn -P release javadoc:jar -DskipTests` (doclint on deprecated surface) —
  BUILD SUCCESS on 2026-07-30, all modules, no doclint errors on the deprecated
  surface. **Re-run after any further code change.**
  - **Gotcha:** this goal runs standalone, so it resolves inter-module deps from
    `~/.m2`, not the reactor. Straight after a version bump the new SNAPSHOT
    artifacts aren't installed and it fails with `Could not find artifact
    ...:mocapi-model:jar:<new-version>` — which looks alarming and is not a doclint
    problem. Run `mvn install -DskipTests` first.
- [x] Full `mvn verify` — BUILD SUCCESS on 2026-07-30; **1228 tests**, 0 failures,
  0 errors. **Re-run after any further code change.**
  - Count from the surefire XML, not the `.txt` summaries: a class whose tests all
    live in `@Nested` inner classes reports `Tests run: 0` in its `.txt`, so
    summing those undercounts badly (it read as 550 before this was caught).
- [x] **B4a — Dev version bump** 0.18.0-SNAPSHOT → **1.0.0-SNAPSHOT** across all
  **24** poms (the earlier "25 poms" count was wrong) via
  `mvn versions:set -DnewVersion=1.0.0-SNAPSHOT -DgenerateBackupPoms=false`. Per the
  OSS runbook the pom stays `-SNAPSHOT` in git at all times; `maven-publish.yml`
  strips it ephemerally in CI. Done as prep so `main` gets a real CI + Sonar run on
  the 1.0.0 coordinates before the tag.
- [ ] **B4b — README dependency snippets** (`README.md:49,61`) still quote `0.17.0`,
  the last released version — correct today, since 1.0.0 isn't on Maven Central yet.
  Bump these **at tag time**, not before, or the README advertises a version that
  doesn't resolve. The Maven Central badge is dynamic and needs no change.
- [ ] **Cut the release** — `gh release create 1.0.0` (bare semver, no `v` prefix)
  is what triggers `maven-publish.yml`. A plain tag push publishes nothing.
  **Last.**
