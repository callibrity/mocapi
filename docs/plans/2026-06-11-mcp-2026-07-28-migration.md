# MCP 2026-07-28 Clean-Break Rewrite Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Rebuild mocapi as a native MCP 2026-07-28 server framework — stateless core, `server/discover`, MRTR elicitation — as if the library had been designed against this revision from the start. No legacy protocol support, no dual paths.

**Architecture:** Every request is self-contained: protocol version, client identity, and client capabilities arrive in `_meta`; the server holds no per-client state. There is no handshake, no session, no session store, and no server-initiated request channel. Elicitation works by replay: the server returns `InputRequiredResult` with a signed/encrypted self-contained `requestState`, and the handler re-executes when the client retries with answers. Deprecated spec features (Roots, Sampling, Logging) are not implemented — a fresh 2026-07-28 implementation would not adopt them.

**Tech Stack:** Java 21+, Spring Boot, Jackson, Maven multi-module. Substrate and Odyssey are removed entirely: sessions and the Mailbox rendezvous are gone, and the draft transport spec states "Resumable SSE streams via `Last-Event-ID` are not supported" — so the journal-backed stream replay and Odyssey's named/resumable stream management (`DefaultSseStream`/`DefaultSseStreamFactory`) lose their purpose too. The new per-request SSE response stream is plain Spring `SseEmitter` (see Phase 7).

**Source of truth:** [Draft spec changelog](https://modelcontextprotocol.io/specification/draft/changelog) (RC locked 2026-05-21; final ships 2026-07-28). Re-verify against final before release (Phase 9).

---

## Design stance (the "from the get-go" rules)

1. **No sessions, anywhere.** `McpSession`, `McpSessionService`, session storage, and `Mcp-Session-Id` handling are deleted, not bypassed. Capability gating reads per-request `_meta`. Cross-call application state uses the spec's explicit-handle pattern (tools return IDs the model passes back) — that's a userland pattern documented in guides, not framework machinery.
2. **No server-initiated requests.** The Mailbox rendezvous (`McpResponseCorrelationService`, ADR-0008) is deleted. Elicitation is MRTR replay. There is no other server→client request in the protocol anymore.
3. **Deprecated features are not implemented.** Roots: never used anyway. Sampling: `ctx.sample(...)` and its plumbing are removed — spec migration guidance is "integrate directly with LLM provider APIs." MCP Logging: `ctx.log(...)`-to-`notifications/message` is removed — guidance is stderr (stdio) or OpenTelemetry, which mocapi-otel already covers. **Progress notifications are NOT deprecated** — `notifications/progress` stays, flowing on the request's own response stream.
4. **Model stays 1:1 with `schema.ts`** (ADR-0014 unchanged): types the spec *removed* get deleted; types the spec *deprecated* stay in `mocapi-model` with `@Deprecated` (spec-contract suppression rule applies to their round-trip tests), but nothing in `mocapi-api`/`mocapi-server` references them.
5. **Single supported protocol version:** `"2026-07-28"`. `server/discover` advertises exactly that. Anything else → `UnsupportedProtocolVersionError`. A legacy client POSTing `initialize` gets a method-not-found/unsupported-version error — acceptable; there are no current consumers.
6. **Not implemented in this revision** (ADR-0018 successor): `subscriptions/listen` (mocapi has no change notifications to push — discovery is static at startup), Tasks extension (`io.modelcontextprotocol/tasks`), MCP Apps extension, URL-mode elicitation, cancellation processing, JSON-RPC batching (still spec-prohibited).

## What this deletes vs. builds

| Deleted | Built in its place |
|---|---|
| `initialize`/`initialized` handshake, version negotiation in `DefaultMcpServer.createContext()` | `_meta` envelope parsing + `server/discover` |
| `McpSession`, `McpSessionService`, session storage, `SessionMcpContext` | Per-request `McpExchange` (immutable, parsed from `_meta`) |
| `McpResponseCorrelationService` + Substrate Mailbox rendezvous | MRTR replay engine + `RequestStateCodec` |
| `ctx.sample(...)`, `ctx.log(...)`, roots handling, `ping`, `logging/setLevel` | — (progress notifications remain) |
| HTTP GET SSE stream, `Mcp-Session-Id` header handling, `Last-Event-ID` resumability + encrypted event IDs + journal | POST-only endpoint; SSE on POST responses for request-scoped notifications; stream close = cancellation |
| Substrate dependency (sessions, Mailbox, journal all obsolete) | — |
| Odyssey dependency (`DefaultSseStream`/`DefaultSseStreamFactory` — named, session-keyed, resumable streams) | Plain per-request Spring `SseEmitter` scoped to the POST response |
| Substrate-showcase examples (Redis/Postgres session stores) | Stateless multi-instance example |

Smaller adds: `Mcp-Method`/`Mcp-Name` required request headers; `ttlMs`/`cacheScope` on the five cacheable results; deterministic list ordering; `-32602` for resource-not-found; full JSON Schema 2020-12 tool schemas; `extensions` map on capabilities (advertised empty); W3C trace context from `_meta`.

## Phase 3 — Transports

### Task 3.1: Streamable HTTP rewrite
**Files:** Rewrite `mocapi-streamable-http-transport/.../StreamableHttpController.java` + tests.
Requirements pinned from the draft transport spec (fetched 2026-06-11):
- POST-only MCP endpoint. Delete the GET SSE stream and all `Mcp-Session-Id` handling. GET or DELETE → `405 Method Not Allowed`. An incoming `Mcp-Session-Id` header is ignored (never minted/echoed); `Last-Event-ID` is ignored — **resumability is removed from the spec** ("Resumable SSE streams via `Last-Event-ID` are not supported"). Delete the encrypted-event-ID + journal machinery and the Odyssey-backed `sse/DefaultSseStream` + `DefaultSseStreamFactory`; the per-request response stream is a plain Spring `SseEmitter` owned by the controller (also remove the Odyssey bean wiring in `mocapi-autoconfigure/.../StreamableHttpAutoConfiguration.java`).
- Required headers, validated against the body: `MCP-Protocol-Version` (must equal `_meta` `io.modelcontextprotocol/protocolVersion`), `Mcp-Method` (all requests and notifications, must equal `method`), `Mcp-Name` (on `tools/call`/`resources/read`/`prompts/get`, must equal `params.name`/`params.uri`). Missing/mismatched/malformed → `400` + JSON-RPC error `-32001` `HeaderMismatch`.
- Unknown RPC method → `404` + JSON-RPC `-32601` (distinguishes a modern server from a legacy HTTP+SSE 404).
- Unsupported protocol version → `400` + `UnsupportedProtocolVersionError` listing supported versions.
- SSE on the POST response stays for request-scoped notifications (`notifications/progress`) while a call is in flight; final response SHOULD terminate the stream; include `X-Accel-Buffering: no`.
- **Client disconnect = cancellation**: server MUST NOT send further messages for that request (automatic on close) and SHOULD stop work — best-effort only given virtual threads without cooperative cancellation; record the partial stance in ADR-0022 (carries over ADR-0018's cancellation rationale).
- `x-mcp-header` is **optional for servers** (`MAY` designate params). Skip it: mocapi designates none, and unrecognized `Mcp-Param-*` headers are simply ignored per RFC 9110. Record in ADR-0022 as a possible future `@McpTool` parameter annotation.
- Keep existing `Origin` validation (`403` on invalid).
TDD: stateless POST happy path (JSON and SSE responses); each header-validation failure mode → `-32001`; unknown method → `404`/`-32601`; GET/DELETE → 405; progress notification mid-call; legacy `initialize` POST → clean modern error.

### Task 3.2: stdio simplification
**Files:** Modify `mocapi-stdio-transport`: remove handshake gating; `server/discover` answerable at any time as the back-compat probe; every request parsed through `MetaEnvelopeParser`. Tests: discover-first flow; tool call with `_meta` envelope; missing envelope → error.

## Phase 4 — MRTR elicitation (replay engine)

### Task 4.1: `RequestStateCodec`
**Files:** Create `mocapi-server/.../mrtr/RequestStateCodec.java` + tests.
Encodes `{method, originalParams, inputResponses[], issuedAt}` → signed+encrypted opaque string. Key from config (`mocapi.mrtr.secret`; generate-and-log-warning default for dev, required-in-prod posture — match how the old SSE event-ID encryption handled key config, or simplify if that machinery died in Task 3.1). Tests: round-trip, tampered → rejected, expired (`mocapi.mrtr.ttl`, default aligned with old elicitation timeout) → rejected.

### Task 4.2: Replay engine
**Files:** Create `mocapi-server/.../mrtr/MrtrElicitationEngine.java`, internal `ElicitationPendingSignal` (RuntimeException, never user-visible) + tests.
- `ctx.elicit(...)` consults the exchange's response ledger by **call ordinal**: answered → return `ElicitResult` immediately; unanswered → throw signal carrying the built `InputRequest` (the flat-schema `RequestedSchemaBuilder` from ADR-0015 is unchanged).
- Dispatcher catches the signal → `InputRequiredResult` with `requestState` from the codec.
- Retry path: decode + validate `requestState`, append `inputResponses`, re-invoke the handler from the top with the ledger populated.
- Client capability check: `McpExchange.supportsElicitationForm()` false → `McpElicitationNotSupportedException` immediately (this exception type survives).
TDD sequence: one elicit/two round trips; two sequential elicits/three round trips; decline and cancel responses; tampered/expired state; ordinal mismatch (non-deterministic handler) → clear diagnostic error.

### Task 4.3: Docs in lockstep
**Files:** Finalize `docs/design/elicitation-mrtr.md` against real code; rewrite `docs/guides/interactive-tools.md` — remove `ctx.sample`/`ctx.log` sections, document the idempotency contract: *“code before your last `elicit()` call re-executes once per round trip — put side effects after the final elicitation or make them idempotent.”*
